# Архитектура проекта (Feature-Sliced Design)

Проект использует упрощенную методологию Feature-Sliced Design (FSD). Код разделен на слои, которые имеют строгую иерархию импортов.

## Слои (от высшего к низшему)

1. **app/** — Инициализация приложения: провайдеры, роутер, глобальные стили, Redux store.
2. **pages/** — Страницы приложения (композиция виджетов и фич).
3. **widgets/** — Самостоятельные крупные блоки интерфейса (Header, Sidebar).
4. **features/** — Действия пользователя, несущие бизнес-ценность (форма поиска, добавление слова).
5. **entities/** — Бизнес-сущности (Курс, Слово, Пользователь) — их UI и модели данных.
6. **shared/** — Переиспользуемый код, не привязанный к бизнес-логике (UI-кит, хелперы, базовый API-клиент, конфиги).

## Правило зависимостей (Главное правило)

Слой может импортировать код **только из слоев, которые находятся НИЖЕ него**.

- `app` может импортировать всё.
- `pages` могут импортировать `widgets`, `features`, `entities`, `shared`.
- `widgets` могут импортировать `features`, `entities`, `shared`.
- `features` могут импортировать `entities`, `shared`.
- `entities` могут импортировать **только** `shared`.
- `shared` **не импортирует ничего** из других слоев (это фундамент).

## Правило: когда использовать `interface`, а когда `type`

В проекте принято следующее соглашение:

- **`interface`** используется для описания формы объектов (сущностей домена).
  _Пример: `Course`, `Teacher`, `User`, `Group`._
  _Почему:_ Интерфейсы лучше подходят для декларации структур данных, которые могут быть расширены (например, при помощи `extends`), и они дают более читаемые сообщения об ошибках в редакторе.

- **`type`** используется для всего остального:
  1. **Объединения (Union types):** когда переменная может принимать одно из нескольких конкретных значений.
     _Пример: `CourseLevel = 'A1' | 'A2' | 'B1' | 'B2' | 'C1' | 'C2'`._
  2. **Утилитарные типы:** когда мы создаем новый тип на основе существующего (с помощью `Omit`, `Pick`, `Partial`).
     _Пример: `CreateCourseData = Omit<Course, 'id'>`._
  3. **Кортежи и примитивы:** _Пример: `type ID = string | number`._
